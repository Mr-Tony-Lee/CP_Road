# LeetCode 17. Letter Combinations of a Phone Number

## 1. 核心思維：回溯法 (Backtracking)

我們的目標是根據給定的數字字串（來自電話按鍵），找出所有可能的字母組合。

這是一個典型的**組合問題**，適合使用 **回溯法 (Backtracking)** 或稱 **深度優先搜索 (DFS)** 來遍歷所有可能的結果路徑。當我們處理到字串的最後一個數字時，就代表找到了一組完整的字母組合。

## 2. 解題策略：映射表 + 遞迴

### 建立數字與字母的映射

電話按鍵上的每個數字（2-9）都對應到 3 或 4 個英文字母。我們可以預先建立一個映射表（在本實作中為 `arr` 陣列），讓我們能根據輸入的數字字元快速找到對應的字母集合。

### 遞迴構造組合

我們定義一個遞迴函數 `recur`，傳入當前正在處理的數字索引 `index` 以及目前的組合字串 `now`：

1.  **終止條件**：當 `now` 的長度等於 `digits` 的長度時，表示我們已經為每個數字選好了一個字母，將 `now` 加入答案集中並回傳。
2.  **遞迴過程**：
    - 取得 `digits[index]` 對應的字母集。
    - 遍歷該字母集中每一個字母：
        - 將字母加入 `now`。
        - 呼叫遞迴函數處理下一個索引 (`index + 1`)。
        - **回溯步驟**：將剛才加入的字母從 `now` 中移除 (`pop_back`)，以便嘗試下一個可能的字母。

## 3. 演算法步驟

1.  **初始化影射表**：建立 `vector<vector<int>> arr`（或字元陣列），存入數字 2 到 9 對應的字母。
2.  **呼叫遞迴函數**：從第 0 個數字開始遍歷，初始組合字串為空。
3.  **遞迴邏輯**：
    - 如果當前組合長度達標，存入結果。
    - 否則，找出當前數字對應的所有字母，逐一嘗試並向下遞迴。
4.  **回傳結果**：等到所有遞迴路徑都探索完畢後，回傳儲存所有組合的 `ans`。

### 複雜度分析

- **時間複雜度**：$O(3^N \times 4^M)$。其中 $N$ 是對應 3 個字母的數字（如 2, 3, 4, 5, 6, 8）個數，$M$ 是對應 4 個字母的數字（如 7, 9）個數。這是因為每一層遞迴都有 3 或 4 個分支，總路徑數即為結果總數。
- **空間複雜度**：$O(N + M)$。這取決於遞迴呼叫堆疊的深度，以及儲存當前路徑 `now` 的空間（不計入最終回傳結果的空間）。
