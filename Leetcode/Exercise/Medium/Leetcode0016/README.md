# LeetCode 16. 3Sum Closest

## 1. 核心思維：排序與雙指標

我們的目標是在陣列中找到三個整數，使它們的和最接近給定的目標值 `target`。

與 3Sum 問題類似，直接使用三層迴圈尋找會導致 $O(N^3)$ 的時間複雜度。透過 **排序 (Sorting)** 陣列並利用 **雙指標 (Two Pointers)** 技巧，我們可以將時間複雜度優化至 $O(N^2)$。在遍歷的過程中，我們持續更新「目前為止最接近目標值的總和」。

## 2. 解題策略：排序 + 雙指標偵測

### 為什麼需要先排序？

1. **具備單調性**：排序後，若當前三數之和小於 `target`，我們可以明確知道需要將左指標右移以增加總和；反之，若和超過 `target`，則將右指標左移以減小總和。
2. **優化搜尋路徑**：排序能讓我們有組織地縮小搜尋範圍，避免重複或無效率的嘗試。

### 雙指標運作機制

固定一個數字 `nums[i]`，並在剩餘範圍 `[i + 1, n - 1]` 內設置雙指標 `left` 與 `right`。
計算 `sum = nums[i] + nums[left] + nums[right]`：

- **完全匹配**：若 `sum == target`，代表找到了最完美的解，直接回傳 `target`。
- **更新最接近值**：計算 `abs(sum - target)`，若比目前紀錄的最小差值 `mmin` 還小，則更新 `mmin` 並紀錄當前的 `sum` 作為答案 `ans`。
- **調整指標**：
    - 若 `sum < target`：表示總和偏小，應將 `left` 右移。
    - 若 `sum > target`：表示總和偏大，應將 `right` 左移。

## 3. 演算法步驟

1. **初步排序**：將 `nums` 進行從小到大排序。
2. **遍歷基準點**：使用迴圈 `i` 從 `0` 遍歷至 `n - 3`。
3. **執行雙指標搜尋**：
    - 初始化 `left = i + 1`, `right = n - 1`。
    - 進入 `while (left < right)`：
        - 計算當前三數之和 `sum`。
        - 如果 `sum == target`，直接結束並回傳結果。
        - 比較 `abs(sum - target)` 與 `mmin`，若更接近則更新答案。
        - 根據 `sum` 與 `target` 的大小關係移動 `left` 或 `right`。
4. **回傳最終答案**：回傳紀錄中最接近 `target` 的總和 `ans`。

### 複雜度分析

- **時間複雜度**：$O(N^2)$。主要耗時在於排序後的兩層遍歷（一層 `for` 迴圈搭配一層雙指標 `while` 迴圈），排序本身為 $O(N \log N)$。
- **空間複雜度**：$O(1)$ 或 $O(\log N)$。主要取決於所使用程式語言內建排序演算法的空間需求。
