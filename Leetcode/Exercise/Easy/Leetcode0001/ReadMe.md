# LeetCode 1. Two Sum

## 1. 核心思維：雜湊表 (Hash Table)

我們的目標是在陣列中找到兩個整數，使它們的和等於給定的目標值 `target`。

最直觀的方法是使用兩層迴圈遍歷所有可能的組合，但這樣的時間複雜度為 $O(N^2)$。為了進一步優化，我們可以使用 **雜湊表 (Hash Table)** 來紀錄已經遍歷過的數字及其索引，將尋找目標補數的時間降低至 $O(1)$，進而達到整體的 $O(N)$ 複雜度。

## 2. 解題策略：單次遍歷與查表

### 為什麼需要雜湊表？

1. **空間換取時間**：我們不再需要回頭重新尋找數字，而是將每個數字存入雜湊表，方便後續快速查找是否存在配對。
2. **單次遍歷即可完成**：在遍歷陣列的過程中，我們同時執行「尋找補數」與「紀錄當前數字」兩個動作。

### 雜湊表運作機制

我們維護一個 `unordered_map<int, int>`，其中 `key` 為數字的值，`value` 為該數字在陣列中的索引。
遍歷 `nums[i]` 時：

- **計算補數**：`complement = target - nums[i]`。
- **查找補數**：檢查 `complement` 是否已存在於雜湊表中。
    - **若存在**：代表我們找到了一組解，直接回傳 `complement` 的索引與當前索引 `i`。
    - **若不存在**：將當前數字 `nums[i]` 及其索引 `i` 存入雜湊表，繼續下一個循環。

## 3. 演算法步驟

1. **初始化**：建立一個空的雜湊表 `answer`。
2. **遍歷陣列**：使用迴圈 `i` 從 `0` 遍歷至 `n - 1`。
    - 計算需要的補數 `target - nums[i]`。
    - 在雜湊表 `answer` 中搜尋此補數。
    - 如果找到補數，則立即回傳 `{answer[complement], i}`。
    - 如果未找到，則將 `{nums[i], i}` 加入雜湊表。
3. **回傳預設值**：若遍歷結束仍未找到解（根據題目假設應至少有一組解），回傳預設值。

### 複雜度分析

- **時間複雜度**：$O(N)$。我們只需遍歷一次陣列，且雜湊表的插入與查詢平均時間複雜度皆為 $O(1)$。
- **空間複雜度**：$O(N)$。在最糟情況下，我們需要將陣列中的所有元素存入雜湊表中。
